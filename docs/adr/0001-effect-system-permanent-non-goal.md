# 0001: 効果システムを永久 Non-Goal とし、純粋性区別の機構選定は先送りする

- ステータス: 採用
- 日付: 2026-07-27

## コンテキスト

言語憲章（`docs/concepts/principles.md`）§8 は "Effect system / macro system" を
Non-Goal に挙げているが、「効果システム」が何を指すかを定義していない。
このため、副作用のある関数と純粋な関数を型で区別する設計が Non-Goal の内側なのか
外側なのかを、憲章だけでは判定できない状態が続いていた。

一方で、コンパイラには既に効果を型で表現する仕組みが 1 本入っている。

- `async fn` の戻り型は組み込み型 `Task(T)` に包まれる（`asatsuyu-ty` の
  `make_task_ty` / `unwrap_task_ty`）
- `is_async: bool` は HIR の `FunctionDef` から THIR まで貫通する関数属性
- `Ty::Function { params, ret }` に効果を保持するスロットは存在せず、
  効果は戻り型の型構築子としてのみ表現されている

つまり「効果を型に載せる」こと自体は既に一度採用済みであり、
禁じ手はもっと狭い範囲にあるはずだが、その線が引かれていなかった。

純粋性区別を実装する際の機構には、確立された選択肢が 3 つある。

1. 単相の型レベルマーカー — `Task(T)` と同じく戻り型を型構築子で包む。
   単一化アルゴリズムは変更不要。高階関数の効果多相は表現できない
2. type-and-effect system — 関数型に効果を持たせ、効果変数を単一化の対象にする
3. 呼び出しグラフ上の不動点計算 — 関数に純粋/非純粋の 2 値属性を与え、
   `extern` を非純粋の種として単調に伝播させる（純粋性解析の古典的形式。
   抽象解釈として定式化できる）

1 と 3 のどちらを採るかは、高階関数（`map` に渡された関数の純粋性が
引数に従属する形）の扱いをプロトタイプで実測しなければ決められない。

## 決定

「効果システム」を **関数型に効果変数を持たせ、それを単一化の対象にする型システム**
（type-and-effect system）と定義し、これを永久 Non-Goal とする。
先送りではなく、恒久的な除外である。

純粋性区別そのものは Non-Goal ではない。ただしその実現機構（上記 1 か 3 か）は
本 ADR では選ばない。高階関数を含むプロトタイプの実測結果をもって、別 ADR で決める。

## 言語憲章との関係

本リポジトリの上位権威は `docs/concepts/principles.md`（言語憲章）であり、
`CONCEPT.md` は作成しない。ADR テンプレートの「CONCEPT.md との関係」は
この憲章との関係を指すものとして読む。

本決定に伴う憲章 §8 の改訂は以下の 3 点。

- "Effect system / macro system" に上記の定義を付し、恒久除外であることを明示する
- "Full native async/await design" を Non-Goal リストから外す。
  `async` / `await` / `Task(T)` は実装済みであり、記述が現物と矛盾していた。
  表層構文として `async` / `await` を残すかどうかは未決として書き分ける
- 純粋性区別が Non-Goal ではないことを明示する

Goals（§2 のミッション、§3 の 5 原則）への影響はなし。

## 検討した代替案

**type-and-effect system を採用する。** 却下。効果変数が単一化に入ると、
型エラーメッセージに効果変数が漏れる。憲章 §2 は評価軸の第一位に
「型エラーメッセージの品質」を固定しており、そこと正面から衝突する。
また §7 が型システムの責務として要求しているのは Hindley-Milner の範囲であり、
効果多相はその枠外。Koka のように効果を型に載せる設計は表現力では上回るが、
Asatsuyu の評価軸では負ける。

**本 ADR で機構（選択肢 1 か 3）まで確定する。** 却下。高階引数の純粋性を
どう扱うかが未検証で、誤った選択は型推論層の手戻りに直結する。
`Ty::Function` の形を変える変更は、424 個のスナップショットと FFI 適合ゲートに
波及するため、実測前に決める利得がコストに見合わない。

**純粋性に一切触れない。** 却下。憲章の Non-Goal 定義が曖昧なままだと、
後続の設計判断のたびにこの議論に戻る。定義を固定するコストは一度きりで済む。

**特定言語の設計をそのまま移植する。** 採らない。Roc は関数名の `!` 接尾辞で
副作用を表面化させ効果を型に載せない方式、Koka は効果を型に載せる方式だが、
本 ADR が固定するのは「効果変数を単一化に持ち込まない」という制約であって、
どちらかの言語の実装ではない。機構を選ぶ段階でも、採用するのは純粋性解析として
確立された一般手法（呼び出しグラフ上の単調な不動点計算、または単相の型レベル
マーカー）であり、特定言語の再現を目的にはしない。

## 影響・結果

- `docs/concepts/principles.md` §8 を上記 3 点で改訂する
- `asatsuyu-ty` の `Ty::Function` は現状維持。効果スロットを追加しない
- 純粋性の機構は次の ADR で決める。判断材料は高階関数を含むプロトタイプの実測
- `Task(T)` は現時点で唯一の型レベル効果マーカーである。純粋性を型に載せる場合、
  `Task(T)` と二重の効果チャネルにならないよう統合を検討する義務が生じる

**この決定を覆す条件（threshold）**: 純粋性の機構として保守的近似（選択肢 3）を採り、
その結果 `map` / `filter` / `fold` 相当の高階関数がすべて非純粋側へ倒れて
標準ライブラリが実用にならないと実測で判明した場合、「効果変数を単一化に
持ち込まない」制約そのものを再検討する。判断は新しい ADR に記録する。

なお、実装計画側（`docs/research/asatsuyu-roadmap.md` の M0-0-3 / 0-4 / 0-5）が
前提していた「AST 以降のクレートを archive する」「42 issue を棚卸しする」
「11 クレート構成を再編する」は、いずれも現物（9 クレート、issue 0 件、
AST 以降は約 33,600 行が稼働中）と一致しないため破棄した。これは設計判断ではなく
計画の事実誤認の訂正なので、別 ADR は起こさない。
